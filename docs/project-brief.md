# Project Brief

## Working Name

Pathport

## One-Line Description

A clean immigration options explorer that helps people understand where they can move and what routes may be available based on their citizenship and circumstances.

## Primary Goal

The main purpose of Pathport is to become a strong portfolio project: a polished, usable application with clean code, thoughtful product decisions, and a UI that feels complete enough to show publicly.

Building a real public product that helps people would be excellent, but it is not the primary constraint at this stage. Scope should stay realistic enough for one developer to finish and present well.

## Problem

Immigration research is fragmented. People often need to compare many practical questions at once:

- Can I enter or stay in this country?
- What visa or residence routes exist for me?
- What are the requirements?
- How expensive is it?
- How long does it take?
- Can I work?
- Can my family come?
- Is there a path to permanent residence or citizenship?
- What official sources should I read before making decisions?

Most existing resources are scattered across government pages, blog posts, law-firm articles, videos, forums, and private chats. They are hard to compare and often written for one nationality, one destination, or one narrow route.

## Target User

Early users are internationally mobile people who are researching relocation options and want a structured starting point before diving into official sources or professional advice.

Possible examples:

- people affected by war, instability, politics, or safety concerns
- remote workers and freelancers
- people looking for work or study routes
- people comparing EU and non-EU options
- people who already ask ChatGPT or online communities for relocation research

## Product Goal

Pathport should turn messy relocation research into a structured comparison experience.

The product should not replace official sources, immigration lawyers, or consulates. It should help users discover possible routes, understand rough tradeoffs, and know what to verify next.

As a portfolio project, Pathport should also demonstrate:

- strong information architecture
- clean TypeScript/JavaScript code
- thoughtful data modeling
- polished responsive UI
- careful handling of uncertainty and source metadata
- a focused MVP that feels finished rather than a huge product that feels thin

## MVP Shape

The MVP can be read-only and data-driven.

A user should be able to:

1. Select a citizenship.
2. Browse destination countries.
3. See available route cards for each country.
4. Compare basic requirements, costs, timelines, and caveats.
5. Open official source links for verification.

The MVP does not need:

- user accounts
- saved profiles
- paid features
- community features
- real-time policy monitoring
- complex eligibility engines
- full global coverage
- perfect data completeness

## Differentiation

Pathport should be different from article-heavy relocation sites by making information structured, comparable, and interface-first.

It should be different from generic AI chat by having persistent data, source links, consistent summaries, and a calm UI optimized for scanning.

## Open Questions

- Which citizenship should be supported first?
- Which destination countries should be included in the first dataset?
- How much content should be human-reviewed before launch?
- Should the first version be English-only?
- How should uncertainty, missing data, and outdated data be displayed?
- Should AI be used only internally for drafting, or should the product include user-facing AI features later?
